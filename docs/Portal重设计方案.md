## 二、设计方向：深空指挥舱（Deep-Space Ops Console）

**一句话**：石墨蓝黑底 + 细网格坐标 + 钛蓝 accent + 切角几何 + 等宽数据字体——Palantir/Vercel 级的"任务指挥中心"气质，矢量感、专业、商业。

- **设计令牌**：底 `#0B0E13` · 面板 `#10141B` · 线 `#222B3A` · 钛蓝 `#4C8DFF`（主accent）· 信号绿 `#2BD590`（正常/节省）· 琥珀 `#F5A623`（警示）· 红 `#FF5C5C`（危险）
- **矢量感来源**：全站 1px 细网格背景、卡片角括号装饰、导航与按钮的**切角 clip-path**、SVG sparkline 趋势线、链路 pipeline 节点图——全部矢量绘制，无渐变滥用
- **字体**：正文 Noto Sans SC · 数据/标签 **IBM Plex Mono**（等宽工程感，全站数字统一等宽呈现）
- **问答前置**：默认视图 = 问答指挥台，Command Bar 置顶，检索调试常驻右栏
- 墨金浅色版（v1 效果图 `design/portal-redesign-mockup.html`）保留备查；深浅两版信息架构一致，只差皮肤

## 三、省 Token 经济（一级设计目标：方案与运行都要省）

**原则：LLM 是最贵的一层，也是最后一层。能不调就不调，调了就省着调。**

### 四层省钱漏斗（按成本从低到高，逐层拦截）

| 层 | 机制 | Token 成本 | 现状 | 实施方式 |
|---|---|---|---|---|
| **L0 精确缓存** | 同问法（归一化：去空格/标点/大小写）直返快照 | **0** | ✅ 已有（AnswerCache，promote 阈值 2） | 无需开发，已上线 |
| **L1 语义近似缓存** | 相似问法向量余弦 ≥0.92 → 直返已有答案 + 标注"近似命中" | **≈0**（只花 1 次查询 embedding） | ❌ 缺 | 复用 bge-m3 向量，对快照问题向量做余弦匹配，**新增 ~40 行** |
| **L2 拒答短路** | 检索最高分 < 阈值（如 0.35）→ 直接拒答，**不调 LLM** | **0** | ❌ 缺（现在低分也空跑 LLM，纯浪费） | 提示词加拒答规则 + app 层短路，**新增 ~20 行** |
| **L3 完整 RAG** | 只有以上都没拦住才走检索+LLM | ~1.6K tok/次 | ✅ 已有 | 上下文做减法（见下） |

### L3 内部再做减法（调 LLM 时省着调）

1. **上下文预算制**：送入 LLM 的引用切片总长 ≤1200 tokens，超出按得分截断（现在整段全送）
2. **答案限长**：fabe.txt 加"答案 ≤150 字"（现均值 214 字，省输出 ~40%）
3. **引用去重**：同文档多切片合并为一个引用块，不重复送

### 预制标准答案（不杜撰的硬约束）

- 入口：问答结果上「**固化为标准答案**」按钮 → 只有**真实 RAG 产出**的答案可固化，人工不能凭空写（UI 不提供空白新建，杜绝杜撰源头）
- 固化记录审计字段：基于哪些切片 ID、KB 指纹、固化时间；**KB 指纹变更后自动降级 stale**，需人工重新审核才能再生效（复用现有 fingerprint 机制，不会拿旧答案冒充）
- 固化答案走 L0 层 0 token 命中，且答案旁标注「标准答案 · 已审核」

### 预期收益（估算口径，上线后以埋点实测为准）

按 100 次/月问答：L0 拦 42% + L1 拦 ~12% + L2 拦 ~30% → **仅 ~18% 查询调 LLM**。每次 LLM 约 1.6K tokens → 月省 **≈11.5 万 tokens（约 82%）**。省算策略面板将显示实测命中率与节省量，不靠估算数字长期糊弄。

### 观测埋点（诚实计量）

app 内存计数（按天持久化）：`queries_total / l0_hits / l1_hits / l2_short / llm_calls / tokens_in / tokens_out`，新增只读端点 `/stats/token-economy`，总览 KPI「本月节省 TOKENS」读真实值——**上线前效果图里的 115K 是占位演示数据，会标注 EST.**

## 五、技术实现（确认后执行）

### 前端（大头）
1. **重写** `code/portal/index.html` 为深空指挥舱（~1100 行），**保留** `{{AUTO_API_KEY}}` 占位符 + `authOnly()` 鉴权注入（P0-1 成果不丢）
2. 零构建、零 npm 依赖（vanilla JS + 内联 SVG + jsDelivr 字体，失败回退系统字体）
3. 问答历史前端 localStorage 持久化（后端无会话存储，不引入新存储）

### 后端小幅扩展（app.py，~150 行，一次部署全带上）
| 新增 | 说明 | 复杂度 |
|---|---|---|
| `PATCH /kb/source/{id}` | 文档重命名（元数据级） | 小 |
| `POST /kb/source/{id}/replace` | 替换内容 → 重新切片向量化，**原子替换**（备份 + 指纹置空） | 中 |
| L1 语义缓存 | 快照问题向量余弦匹配 ≥0.92 直返（env 可关） | 小 |
| L2 拒答短路 | top 分 < 阈值（env `REJECT_THRESHOLD`，默认 0 关闭）不调 LLM | 小 |
| `/stats/token-economy` | 六个计数器只读端点（按天持久化） | 小 |
| `/embed/*` `/cache/*` 接线 | 上周已上线的 API 终于有 UI 入口 | 零后端 |

### 交付节奏（每步独立可回滚）

- **M2 省 Token 三件套**：L1 语义缓存 + L2 拒答短路 + 埋点端点 → A/B 实测命中率 → 部署

## 六、风险与边界

- 效果图数据为**演示假数据**（KPI 已标 EST.），上线后读真实接口
- 检索调试面板：`/query` 现仅返回融合分 → M1 先展示融合分，分路得分需 `/query` 增返回字段（列入 M2，不假造）
- 文档"替换"若中途失败：脚本先备份旧切片再原子写，失败自动回退（复用 upgrade_metadata 的原子写模式）
- 拒答阈值的"低分"判定基于余弦分数分布，阈值 0.35 为初始值，上线后按真实分布校准（老张铁律：参数是起点不是终点）
- 幻觉治理（KB 外自由发挥）由 L2 拒答短路 + 拒答提示词双保险解决，属本次 M2 范围
