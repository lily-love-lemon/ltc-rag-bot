## 三、发布策略

CloudBase 云托管**无灰度/蓝绿能力**（`docs/CloudBase约束.md` 限制 5）。因此：

- **策略 = 全量替换 + 快速回滚兜底**（不是灰度）
- 部署即全量切换，构建期 2–5 分钟
- 兜底靠 `rollback.sh`：git 检出上一版本 → 重新构建部署
- 因此**回滚预案必须先验证过**（本方案的 `deploy_drill.sh` 就是这条前提）

## 四、部署步骤

### 4.0 前置（首次）

```bash
npm i -g @cloudbase/cli
tcb login          # 浏览器扫码
```

### 4.1 前置检查（不部署，先看风险）

```bash
cd "<项目根>/code"
bash deploy.sh --preflight-only
```

检查项：`.env` 与 LLM 密钥、`API_KEY` 是否仍为默认值、git 工作区是否干净、关键文件是否齐全、`cloudbaserc.json` 的 `envParams` 是否为空。

> 该命令**不会**碰线上，安全。

### 4.2 部署

```bash
bash deploy.sh -e lily0625ai-d1gpwc1vw89141edd       # 指定环境
# 或
bash deploy.sh                                        # 交互式列出环境让你选
```

脚本实际发出的命令（与 `docs/CloudBase约束.md` 限制 5 的实测形式一致）：

```bash
tcb cloudrun deploy -s ltc-rag-bot -e <envId> --force
```

`--force` 跳过确认，空输入自动选「非灰度」，避免卡在交互提示。

### 4.3 部署后（手工，控制台）

1. 云托管 → `ltc-rag-bot` → 存储 → 开启 **COS 挂载**，路径填 `/mnt/chroma`
2. 云托管 → `ltc-rag-bot` → 环境变量 → 按 `docs/环境清单.md` 第三节逐条添加（**必做的漏项**）
3. 拿到服务 URL

### 4.4 部署后验证（必做，勿跳）

```bash
curl -s <服务URL>/health                                  # 期望 200
curl -s -H "X-API-Key: <生产KEY>" <服务URL>/kb            # 期望 200；401 = 环境变量没配好
curl -s -X POST -H "X-API-Key: <生产KEY>" -H "Content-Type: application/json" \
  -d '{"question":"LTC 交付流程分几步？","top_k":5}' <服务URL>/query
```

完整验收用例见 `docs/13项冒烟验收.md` 第二节 A1–A4 与 `docs/部署验证用例与报告.md`。

## 五、风险评估

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| **重部署后环境变量丢失 → 线上无 LLM 密钥** | 中（线上已配好，但需确认 `tcb deploy` 不清除控制台变量） | RAG 退化为模板拼接 | 重部署后必须按 `docs/上线巡检记录表.md` 复测 `/health` 的 `api_key_mode=生产模式` + `/query` 真调 LLM；`cloudbaserc.json` 的 `envParams` 刻意留空，不接管密钥 |
| `API_KEY` 用默认值上线 | 高（`.env` 里 `API_KEY` 是注释态） | 接口公开可调用 | preflight 明确告警；4.3 第 2 步 |
| COS 未挂载 → 入库数据写容器本地 | 中 | 容器回收后**知识库丢失** | `app.py` 启动日志打印实际 store path；部署后确认路径为 `/mnt/chroma` |
| **规格静默降级（0.5核/128MB vs 飞书称线上 2核/2GB）** | **高（重部署高危）** | 实例被降到 128MB，可能 OOM / 性能骤降 | ⚠️ 重部署前**必须控制台核实真实规格**，把 `cloudbaserc.json` 的 `cpu/mem` 改为与控制台一致；**未核实禁止 `bash deploy.sh`** |
| 冷启动 2–5s | 确定 | 首个请求慢 | Portal 加 loading 态 |
| 回滚误操作（部署了当前代码却以为回滚了） | 中 → **已消除** | 故障期间无法恢复 | `rollback.sh` v2：无效目标直接中止（exit 2），不再假回滚 |

## 六、上一版脚本的 3 个缺陷（本方案已修复，留档）

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | 部署命令写成 `tcb cloudrun deploy --envId X --servicePath .`，与实测形式 `-s <service> -e <env> --force` 不一致 | 缺 `--force` 会**卡在灰度交互提示**，无人值守必挂 |
| 2 | 结尾文案称「环境变量已在 cloudbaserc.json 里配置」，实际 `envParams` 为 `{}` | 误导运维，导致线上无密钥 |
| 3 | `read -p` 在 `set -e` 下遇 stdin 关闭直接退出 | 无法在 CI / 非交互环境执行 |
