## 一、为什么能离线验证

`deploy.sh` / `rollback.sh` 对 CloudBase 的全部依赖都收敛到 `tcb` 这一个命令。
把 `tcb` 换成一个只记录调用、返回可预期输出的 stub，就能在**不联网、不装 CLI、不动线上**的前提下，
把两个脚本的**控制流与命令参数**完整跑一遍 —— 这正是回滚脚本最需要验证的部分（逻辑错 = 假回滚）。

| 项 | 说明 |
|---|---|
| 演练场 | `git clone` 出的临时副本（**带全部 tag**，否则测不了回滚） |
| stub 位置 | `<临时目录>/bin/tcb`，通过 `PATH` 前置生效 |
| 调用记录 | 每次 `tcb` 调用原样写入 `tcb_calls.log` |
| 被测脚本 | 从工作区 `cp` 进演练场 —— 测的是「即将提交的版本」，不是历史版本 |
| 副作用 | 临时目录用完即删（`--keep` 可保留）；**主仓库、线上数据零改动** |
